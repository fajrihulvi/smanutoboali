# S04 — Autentikasi multi-role

## Rencana

1. `App\Modules\Core\Enums\Role` (principal/teacher/operator/guardian/applicant): label, prefix URL, route prefix, slug portal login, route dashboard.
2. Pasang `spatie/laravel-permission` (config + migrasi). Migrasi modul Auth: `users.public_id` (ULID), `is_active`, `last_login_at`.
3. Modul **Auth**:
   - `GET /login` pilihan 4 portal; `GET|POST /login/{portal}` (`kepala-sekolah|guru|operator|orang-tua`).
   - `AttemptPortalLoginAction`: rate limit 5x/menit per email+IP; kredensial + role portal harus cocok, selain itu pesan generik "Email atau password salah."; akun nonaktif ditolak; session regenerate + `active_role`.
   - `POST /logout` → kembali ke halaman login portal role terakhir.
   - `POST /switch-role/{role}` (validasi user punya role).
   - Lupa & reset password (password broker Laravel) dengan notifikasi email Bahasa Indonesia.
4. Middleware alias `active.role` (+ logout paksa bila akun dinonaktifkan) dan shared props Inertia: `auth.user` (AuthUserResource), `auth.roles`, `auth.activeRole`, `auth.permissions`, `flash`.
5. Modul **Dashboard**: placeholder per role (judul + StatCard dummy); Orang Tua memakai ParentLayout.
6. Seeder akun demo (CLAUDE.md) + satu akun multi-role untuk mencoba role switcher.
7. Test Pest: login per role, portal salah ditolak, akun nonaktif, 403 lintas portal, rate limit, role switcher, logout, lupa/reset password, register tidak ada.

## Keputusan

- **Laravel Fortify dihapus.** `POST /login` bawaan Fortify tidak mengenal portal/role sehingga menjadi jalur bypass; registrasi publik harus mati; 2FA, verifikasi email, dan konfirmasi password tidak ada di spesifikasi. Halaman Keamanan tinggal ganti password.
- Akun nonaktif yang memasukkan kredensial & portal yang benar mendapat pesan spesifik ("Akun Anda dinonaktifkan…"); karena butuh password yang benar, tidak membocorkan keberadaan akun.
- `redirect()->intended()` hanya dipakai bila URL tujuan berada di prefix portal yang sama; selain itu ke dashboard role.
- Permission spatie bersifat gabungan semua role user; batas portal dijaga oleh middleware `active.role` pada prefix route. Menu (`auth.permissions`) memakai permission milik role aktif saja.
- Role `applicant` belum punya portal login (dibuat di S26 `/ppdb/masuk`).

## Hasil

- Keempat akun demo login ke portal masing-masing lewat server lokal (MariaDB) dan ditolak di portal lain (diverifikasi dengan curl + token CSRF).
- 54 test lulus (login per role ×4, portal salah, password salah, akun nonaktif, rate limit, 403 lintas portal, role switcher, logout per portal, lupa/reset password, register 404, pengaturan akun).
- pint, phpstan (level 6), eslint, prettier, tsc, build hijau.
- Audit login/logout/switch role disiapkan di S07 (activitylog belum terpasang di sesi ini).
