# S16 — Raport + workflow approval + PDF

## Rencana

1. Modul baru **ReportCard**:
   - `report_cards` (student, classroom, semester, academic_year, status, homeroom_note, attendance snapshot, published_at; unik siswa+semester; soft delete).
   - `report_card_details` (mapel: nama, kelompok, nilai akhir, predikat, deskripsi — snapshot dari Assessment).
   - `report_card_extracurriculars`, `report_card_achievements` (isian bebas wali kelas).
   - `report_card_logs` (dari → ke, siapa, kapan, catatan).
   - `report_subject_confirmations` (penugasan × semester, dikonfirmasi oleh/kapan).
   - `report_card_exports` (cetak massal: status, file ZIP).
2. Enum `ReportCardStatus` dengan `canTransitionTo()`; semua transisi lewat `TransitionReportCardAction` (+ log).
3. Alur (sesuai jawaban pengguna):
   - Wali kelas **generate DRAFT** (nilai akhir & deskripsi dari Assessment + rekap presensi semester), isi catatan, ekskul, prestasi.
   - Guru mapel **mengonfirmasi** mapelnya per rombel (syarat: semua siswa punya nilai akhir & deskripsi). Konfirmasi terakhir → semua raport DRAFT rombel itu otomatis **SUBMITTED** (detail disegarkan).
   - Wali kelas review → **HOMEROOM_REVIEWED**; operator → **VALIDATED**; kepala sekolah → **APPROVED** (massal per rombel); operator → **PUBLISHED** (massal) + notifikasi orang tua.
   - Tiap tahap bisa dikembalikan ke **REVISION** dengan catatan wajib; operator bisa menarik PUBLISHED → REVISION. Dari REVISION wali kelas "ajukan ulang" → SUBMITTED (bila konfirmasi mapel masih lengkap).
4. PDF via dompdf (logo sekolah, tanda tangan kepala sekolah dari Pengaturan Sekolah, tanda tangan wali kelas dari profil guru); cetak massal per rombel lewat Job → ZIP.
5. Orang tua hanya melihat/unduh raport PUBLISHED.
6. Test: transisi ilegal ditolak, orang tua tidak bisa akses DRAFT, guru non-wali tidak bisa review, konfirmasi mapel.

## Keputusan

Dari jawaban pengguna:

- SUBMITTED dicapai otomatis setelah **semua guru mapel mengonfirmasi**; review oleh wali kelas.
- Tanda tangan: kepala sekolah di Pengaturan Sekolah; wali kelas di profil guru (tanpa gambar → ruang kosong untuk tanda tangan basah).
- Ekskul & prestasi: isian bebas per raport.
- Operator bisa menarik raport PUBLISHED ke REVISION (catatan wajib).

Diambil sendiri:

- **Publikasi** dilakukan operator (bisa massal) setelah kepala sekolah menyetujui — memisahkan persetujuan isi dan waktu rilis ke orang tua.
- Isi raport (catatan, ekskul, prestasi) bisa diubah wali kelas selama DRAFT / REVISION / SUBMITTED; mulai HOMEROOM_REVIEWED terkunci.
- Detail nilai adalah **snapshot**: dibuat saat generate dan disegarkan otomatis saat raport menjadi SUBMITTED, sehingga perubahan nilai setelah itu tidak mengubah raport yang sedang diproses.
- Guru mapel hanya bisa membatalkan konfirmasi selama semua raport rombel masih DRAFT/REVISION.
- Presensi di raport = jumlah hari **sakit, izin, tanpa keterangan (alpa)** dalam rentang tanggal semester (dari status harian S13).
- Kelompok mapel mengikuti `SubjectGroup` (Umum, Pilihan, Muatan Lokal) untuk pengelompokan di PDF.
- ZIP massal disimpan sebagai file privat (FileService) dan bisa diunduh peminta selama 7 hari; diproses antrean `database` lewat scheduler.
- PDF memakai font DejaVu Sans dengan **font subsetting** aktif: satu raport ±28 KB (tanpa subsetting ±880 KB — ZIP satu rombel bisa puluhan MB). `enable_remote` dompdf tetap nonaktif; gambar disematkan sebagai data URI.
- PDF raport yang belum terbit diberi watermark "DRAF — BELUM TERBIT".

## Hasil

- Modul **ReportCard**: tabel `report_cards`, `report_card_details`, `report_card_extracurriculars`, `report_card_achievements`, `report_card_logs`, `report_subject_confirmations`, `report_card_exports`; kolom `schools.principal_signature_file_id` & `teachers.signature_file_id`.
- `ReportCardStatus::canTransitionTo()`, `TransitionReportCardAction` (satu-satunya jalan ubah status: cek transisi, hak pelaku per tahap lewat `ReportCardAccess`, catatan wajib REVISION, log + audit, event `ReportCardPublished` → notifikasi orang tua).
- `ReportCardGenerator` (snapshot nilai/predikat/deskripsi via `GradeRecap` + rekap presensi semester), `SubjectConfirmations` (kesiapan mapel, konfirmasi, auto-SUBMITTED, ajukan ulang), `ReportCardPdf` (dompdf + Blade modul `report-card::pdf`), job `GenerateReportCardZip` (+ prune 7 hari).
- Guru `/guru/raport`: konfirmasi mapel (dengan alasan bila belum siap) + rombel perwalian → buat/perbarui draf, review massal, kembalikan revisi, isi catatan/ekskul/prestasi per raport.
- Operator `/operator/raport`: ringkasan status per rombel, validasi & terbitkan massal, tarik raport terbit, cetak massal ZIP. Kepala sekolah `/kepala-sekolah/raport`: setujui massal / kembalikan revisi. Orang tua `/orang-tua/raport`: raport terbit + unduh PDF.
- Unggah tanda tangan: Pengaturan Sekolah (kepala sekolah) & profil guru (wali kelas) lewat `ReplaceSignatureAction` (privat, maks 1 MB).
- Infrastruktur: `ModuleServiceProvider` kini memuat Blade view modul (`resources/views` → namespace kebab-case); label modul audit log `attendance`, `assessment`, `report_card` ditambahkan (terlewat di S13/S15).
- **Masalah yang ditemukan & diperbaiki:** lazy loading relasi model hasil route binding (ditangkap `preventLazyLoading`) → `loadMissing` di titik masuk; halaman detail melebar di 360px karena item grid `min-width:auto` → `min-w-0`.
- Seeder demo: VIII-A seluruh alur sampai TERBIT (Rafi, anak `ortu@`, bisa langsung dilihat/diunduh); VII-A (wali `guru@`) DRAF menunggu konfirmasi Matematika milik `guru@`.
- 406 test Pest + 19 Vitest lulus; pint, phpstan, eslint, prettier, tsc, build hijau. Screenshot 1440/360 tanpa overflow horizontal; PDF diperiksa visual.
