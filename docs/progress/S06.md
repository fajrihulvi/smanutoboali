# S06 — User management & Role/Permission UI

## Rencana

1. `/operator/users` (permission `user.manage`): DataTable (nama, email, role, status, login terakhir), filter role & status, pencarian, paginasi server-side; buat/edit user dengan multi-role; reset password; aktif/nonaktifkan.
2. `/operator/roles` (permission `role.manage`): daftar role (jumlah user & permission) → halaman edit permission per role berupa checkbox yang dikelompokkan per modul (`Permission::group()`).
3. `last_login_at` sudah dicatat sejak S04 (`AttemptPortalLoginAction`); ditampilkan di tabel.
4. Audit: pasang tabel spatie/activitylog sekarang, bungkus lewat `App\Modules\Core\Services\AuditLogger`; semua Action S06 mencatat log `access`. Konfigurasi penuh (ip/user agent, halaman) di S07.
5. Actions: CreateUser, UpdateUser, ResetUserPassword, SetUserActiveStatus, UpdateRolePermissions. Policies: UserPolicy, RolePolicy.
6. Test akses (role lain 403, tanpa permission 403), validasi, ownership aturan diri sendiri.

## Keputusan

- **Tidak ada buat/hapus role kustom.** Portal & menu bergantung pada 5 role inti; role tambahan tidak punya portal sehingga permission-nya tidak konsisten. Halaman role hanya mengedit permission 5 role inti (yang otomatis "tidak bisa dihapus"). `RolePolicy::delete()` selalu false untuk role inti.
- Operator **tidak bisa** menonaktifkan dirinya, mencabut role `operator` dari dirinya, atau mencabut `role.manage` dari role operator (mencegah terkunci dari sistem).
- Reset password oleh operator: operator mengisi password baru (ada tombol "buat acak"); semua sesi user tersebut dihapus. Menonaktifkan user juga menghapus sesinya.
- Operator menetapkan password awal saat membuat user (belum ada email undangan).

## Hasil

- Halaman `/operator/users`, `/operator/users/create`, `/operator/users/{public_id}/edit`, `/operator/roles`, `/operator/roles/{role}/edit` dicek lewat login sungguhan (puppeteer) di 1440px & 360px: tanpa scroll horizontal.
- Menu "Profil" orang tua sementara diarahkan ke `/settings/profile` (halaman profil orang tua dibuat di S09).
- Audit log `access` tercatat untuk: buat/ubah user, reset password, aktif/nonaktif, ubah permission role.
- 105 test Pest + 7 Vitest lulus; pint, phpstan, eslint, prettier, tsc, build hijau.
