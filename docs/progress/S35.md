# S35 — Deploy produksi

## Rencana

1. **Geladi staging di lokal**, karena belum ada server staging: arsip rilis dari `scripts/build-release.sh` diekstrak ke folder baru dengan database baru dan `.env` produksi. Langkah `docs/DEPLOY_CPANEL.md` dijalankan persis (tanpa Node, tanpa file sumber), lalu aplikasi dicek lewat browser. Temuan dipakai untuk memperbarui skrip & panduan.
2. **`scripts/build-release.sh`**: verifikasi manifest build, checksum SHA-256, pembersihan tambahan (file pengembangan), ringkasan isi arsip.
3. **`docs/DEPLOY_CPANEL.md`**:
   - `.env` lengkap (Pusher, Midtrans produksi, backup, log, CSP);
   - seeder produksi, tabel cron lengkap;
   - backup & **restore**, rilis berikutnya (maintenance + secret bypass);
   - checklist go-live.
4. **Checklist go-live otomatis** `php artisan skoolia:go-live-check`:
   - APP_ENV/APP_DEBUG/HTTPS/APP_KEY, mail produksi, kunci Pusher & Midtrans produksi;
   - cron berdetak, backup terakhir sehat, akun demo tidak ada, tidak ada akun admin berpassword `password`;
   - build aset ada, storage bisa ditulis, ekstensi PHP;
   - exit code ≠ 0 bila ada yang gagal.
5. **Seeder produksi** (`ProductionSeeder`): hanya role & permission + profil sekolah + satu akun operator dari `.env` (`OPERATOR_NAME`, `OPERATOR_EMAIL`, `OPERATOR_PASSWORD`, password kuat); aman dijalankan ulang. `php artisan db:seed` di produksi otomatis memakai seeder ini (tidak pernah data demo).
6. **`docs/PANDUAN_PENGGUNA.md`**: panduan singkat per role (operator, kepala sekolah, guru, orang tua, calon pendaftar PPDB) untuk pelatihan.
7. Tag **`v1.0.0`**.

## Keputusan

- **Geladi staging dilakukan di lokal** dengan database terpisah (`skoolia_staging`) dan `APP_ENV=production`. HTTPS tidak bisa diuji di lokal, sehingga pemeriksaan HTTPS di `go-live-check` memang akan gagal di geladi — itu perilaku yang benar.
- **`OPERATOR_PASSWORD` hanya dibaca saat seeding.** Panduan meminta menghapusnya dari `.env` setelah akun dibuat, dan `go-live-check` memberi peringatan bila masih ada.
- **Pemeriksaan password lemah dibatasi ke akun operator & kepala sekolah** (bcrypt per akun mahal). Akun demo dikenali dari domain `@skoolia.test`.

## Hasil

- **Geladi staging lokal:**
  - arsip `skoolia-1.0.0-rc1.zip` (18 MB) diekstrak ke folder baru dengan database `skoolia_staging` dan `APP_ENV=production`;
  - langkah panduan dijalankan persis: `key:generate`, `migrate`, `db:seed` (ProductionSeeder), hapus `OPERATOR_PASSWORD`, `storage:link`, `optimize`, satu putaran cron;
  - lalu: login operator, **47 halaman operator + website** dibuka di browser, 45 halaman guru/orang tua/kepala sekolah (data demo), `/health` dengan token, 404, sitemap/robots, header keamanan;
  - mode perbaikan (`down --render --retry --secret` → bypass → `up`), backup, dan `go-live-check`.
- **Temuan geladi & perbaikannya:**
  1. **CSP `upgrade-insecure-requests` di situs http** membuat navigasi & request Inertia setelah login dialihkan ke https dan gagal (`ERR_CONNECTION_CLOSED`) → hanya dikirim pada request HTTPS (+ test).
  2. **Halaman Banner CMS crash (`s.map is not a function`)**: prop dikirim sebagai `{data: [...]}` sejak S28 → `->resolve()` (+ test halaman kosong & berisi). Screenshot S28 hanya mengecek overflow sehingga tidak menangkapnya.
  3. **Nilai `.env` berspasi tanpa kutip** membuat semua perintah artisan gagal → dicatat di panduan (§3) & troubleshooting.
  4. **Halaman website sistem masih draf** di instalasi baru (`/kontak` 404) → langkah "terbitkan halaman" di panduan & pemeriksaan baru di `go-live-check`.
  5. `optimize:clear` menghapus detak scheduler dari cache → panduan meminta menunggu 1 menit sebelum `go-live-check`.
  6. `OPERATOR_NAME=` kosong di `.env` terbaca sebagai string kosong → jatuh ke default.
- **`scripts/build-release.sh`:** verifikasi `manifest.json`, checksum `.sha256`, `.gitattributes` ikut dibuang, mode geladi `ALLOW_DIRTY=1` memakai snapshot `git stash create` (perubahan yang sudah di-`git add`).
- **`ProductionSeeder`:**
  - `db:seed` di produksi hanya role & permission + profil sekolah (`SCHOOL_NAME`/`SCHOOL_LEVEL`) + satu operator (`OPERATOR_*`, password kuat);
  - idempoten, nilai dibaca lewat `config('skoolia.setup')` (tetap jalan saat config di-cache).
- **`php artisan skoolia:go-live-check`** — 27 pemeriksaan (GAGAL/PERINGATAN/OK):
  - aplikasi, keamanan, ekstensi PHP;
  - email, Pusher, Midtrans (deteksi kunci sandbox);
  - cron, backup, akun demo & password lemah;
  - halaman website, aset build, storage, `.htaccess`.
- **`docs/DEPLOY_CPANEL.md`** ditulis ulang untuk v1.0.0:
  - prasyarat (`proc_open`, `mysqldump`, SSL), `.env` lengkap, seeder produksi, tabel cron lengkap;
  - isi awal aplikasi, **backup & restore** (teruji), rilis berikutnya dengan mode perbaikan + secret, log & pemantauan;
  - 16 baris troubleshooting, checklist go-live.
- **`docs/PANDUAN_PENGGUNA.md`**: panduan pelatihan untuk operator, kepala sekolah, guru/wali kelas, orang tua, calon pendaftar PPDB, dan FAQ.
- 5 test baru (seeder produksi, `go-live-check`, banner, CSP http).
- 652 test Pest + 31 Vitest lulus; pint, phpstan, eslint, prettier, tsc, dan build hijau.
