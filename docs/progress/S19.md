# S19 — Pusher broadcasting & notifikasi realtime

## Rencana

1. Broadcasting Pusher: `install:broadcasting --pusher` (+ `pusher/pusher-php-server`), `routes/channels.php`, frontend `laravel-echo` + `pusher-js` di `resources/js/lib/echo.ts`.
2. Channel privat user `App.Models.User.{public_id}` (notifikasi) + pola otorisasi yang dipakai chat (S20).
3. Semua notifikasi yang ada mendapat channel `broadcast`; lonceng topbar menerima notifikasi realtime → toast + badge + daftar. Halaman `/notifikasi` lengkap (filter semua/belum dibaca, tandai dibaca, tandai semua).
4. Hook `useEchoChannel()` (auto-leave saat unmount), status koneksi, fallback muat ulang saat halaman fokus/tersambung ulang, indikator kecil hanya bila terputus.
5. Test: otorisasi channel (milik sendiri vs orang lain), channel broadcast di notifikasi, halaman notifikasi & kepemilikan.

## Keputusan

- **Konfigurasi Echo dari server** (shared prop `realtime`: kunci publik & cluster), bukan `VITE_PUSHER_*` yang ditanam saat build — aset di-build lokal lalu diunggah ke cPanel, sehingga satu build bisa dipakai di staging/produksi dengan kunci berbeda. Kunci Pusher publik memang aman dibagikan; secret tetap di server.
- **Pusher tanpa kunci → otomatis `log`** (AppServiceProvider), agar event `ShouldBroadcastNow` tidak menggagalkan request di lokal/instalasi baru; UI otomatis memakai fallback.
- Nama channel privat user memakai **`public_id`**, bukan id numerik (aturan tidak mengekspos id).
- Notifikasi: kanal `database` & `broadcast` dikirim **segera** (`viaConnections` → `sync`) saat notifikasi diproses, `mail` tetap lewat antrean. Listener pengirim notifikasi massal (nilai, raport, presensi, portofolio) tetap di antrean agar request guru tidak lambat saat ada puluhan orang tua; jadi notifikasi massal tiba ≤ 1 menit (siklus cron), sedangkan event pengguna aktif (chat S20, kondisi anak S22) memakai `ShouldBroadcastNow`.
- Fallback: saat tab kembali fokus (maks sekali per 30 detik) dan saat Pusher tersambung ulang, badge notifikasi dimuat ulang (`only: ['notifications']`).
- Otorisasi auth channel lewat `authorizer` kustom (fetch dengan token XSRF terbaru), bukan header statis, agar tidak gagal setelah token berganti.

## Hasil

- Broadcasting Pusher (`config/broadcasting.php`, `routes/channels.php`): channel privat `App.Models.User.{public_id}` (tanpa id auto-increment), otorisasi hanya pemilik akun.
- Tanpa kunci Pusher, `BROADCAST_CONNECTION=pusher` otomatis turun ke `log` sehingga aplikasi tetap jalan; shared prop `realtime` bernilai `null` dan UI memakai fallback (reload notifikasi saat tab fokus, di-throttle 30 detik).
- Trait `DeliversInApp`: notifikasi absensi, nilai, raport, portofolio, dan selamat datang dikirim ke `database` + `broadcast` secara sinkron (tanpa worker), sedangkan email tetap lewat queue.
- Frontend: `lib/echo.ts` memuat laravel-echo + pusher-js secara **lazy** (chunk terpisah ±74 KB, hanya diunduh bila realtime aktif), hook `useEchoChannel` dan `useRealtimeStatus`, `RealtimeBridge` (toast notifikasi baru, sinkronisasi badge lonceng, indikator saat koneksi terputus).
- Notification center `/notifikasi` untuk semua role (filter Semua/Belum dibaca, paginasi, tandai semua dibaca), dengan layout orang tua yang mobile-first; lonceng punya tautan "Lihat semua notifikasi".
- 433 test Pest + 20 Vitest lulus; pint, phpstan, eslint, prettier, tsc, dan build hijau. Screenshot 1440/360 guru & orang tua tanpa overflow horizontal.
